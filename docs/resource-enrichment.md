# 原文・公式資料の補完運用

## 保存と公開

日次カードはその日の該当更新へ、一覧／検索は採用した日次更新へ移動します。同じリリース URL が後日に再検出されても、古い日次カードから別の日の見出しへ飛ばしません。

`npm run collect` は通常の収集後に `scripts/enrich-resources.mjs` を実行します。全期間のイベントを走査し、未処理・版違い・30 日を超えた確認結果を更新します。取得失敗は 1 時間後から再試行できます。`data/events` と本文はそのまま保持し、検証情報は `data/resources.json` に保存します。Pages build はネットワークアクセスをせず台帳を読み込みます。

キーは原文 URL、機能タイトル、本文要約、機能見出し、差分の hash です。同じ製品・原文・内容の場合だけ確認結果を共有し、同じ名前の別更新へ使い回しません。出典 URL、確認時刻、本文 hash、原文見出しとの対応、採用理由、日本語本文の確認結果を保存します。資料は現在の設定・制限を読む参考資料であり、過去の Stable／Insiders／Experimental／Preview の提供状況を上書きする根拠にはしません。履歴の適用範囲は元の発表・対象リリースに従います。

カード、検索結果、詳細に原文と資料の文書タイトルを表示します。資料は最大 3 件で、原文と同一文書や製品トップページは除きます。日次アーカイブへの導線は既存イベントキーから作る安定したアンカーを使います。原文・資料ボックス自体は検索本文から除外し、資料のタイトルだけで無関係な更新がヒットするのを防ぎます。

## 調査の順序

1. 原文記事の本文、または該当リリースの正確な機能見出しの範囲にある明示リンクを優先します。実在する `id` のみを採用します。
2. 明示資料がない場合は公式ドキュメントの索引を取得し、機能タイトルの複数の固有語と製品の適用範囲が一致する候補を検証します。単に Copilot の名前が一致する資料は採用しません。
3. 人による調査で見つけた候補は `config/resource-documents.json` に検索手段と日時を付けて登録できます。今回の初期候補は実在する GitHub MCP の `github_support_docs_search` と Microsoft Learn MCP の `microsoft_docs_search` で確認しました。候補の登録だけでは採用されず、本文取得・関連性・日本語本文を再確認します。

公式の主な根拠:

- VS Code: https://code.visualstudio.com/docs / https://code.visualstudio.com/updates/v1_109
- GitHub Copilot CLI の MCP: https://docs.github.com/ja/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers
- Azure Skills: https://learn.microsoft.com/ja-jp/azure/developer/azure-skills/overview

GitHub Docs は `/ja/`、Microsoft Learn は `/ja-jp/` の記事本文に十分な日本語がある場合に優先します。日本語ナビゲーションだけの英語本文は英語として扱います。翻訳版の取得失敗は別途記録し、検証済み英語本文を使います。VS Code は確認できる公式英語版を使い、日本語 URL を推測しません。

What's New の日付／フィルター見出しだけの差分は独立機能として解釈せず、表示にも検出記録であることを明記します。現行ページまたは明示リンクをたどった年／月アーカイブで見出しと個別記事が一意に対応すれば、その記事へ解決します。複数の変更を含む場合は実在するアーカイブ項目の id へ移動し、ひとつの製品機能と解釈しません。過去のハブ更新に対象リリースの明示リンクが残っていない場合も URL やフラグメントを推測しません。

原文の明示リンクに古い文書フラグメントが付いている場合、確認できない id は採用しません。本文を確認できた機能別文書にフラグメントなしでリンクし、その理由を `fragmentVerification` に保存します。日本語版の見出し id が異なる場合も、推測せず日本語本文へ移動します。

## 再開、キャッシュ、レート制限

```bash
npm run audit:resources
npm run enrich:resources
npm run enrich:resources -- --limit=25
npm run enrich:resources -- --retry-failed
npm run build:pages
npm test
```

各入力の完了ごとに台帳を一時ファイルから置き換えてチェックポイントを保存します。中断時は同じコマンドで未完了分から再開できます。入力数を制限しても、監査の母数は全期間です。

取得ページは `.cache/resource-pages` に本文の抽出結果と hash を保存し、成功は 7 日、失敗は 1 時間キャッシュします。逐次取得は最低 200 ms 間隔、25 秒 timeout、429／502／503／504 は最大 3 回まで、Retry-After を尊重して最大 60 秒待機します。リダイレクト先も許可された公式／収集元のホストに限定します。TLS 検証を無効にしません。Actions はこのキャッシュを引き継ぎ、台帳は通常の collect commit に含めます。

## 状態と監査

同じイベント ID が複数のログにある場合、最も新しい検出日時の内容を代表として集計します。同時刻の異なる内容は入力 hash で決定し、ログを昇順／降順のどちらで読む collect と Pages でも同じ件数になります。

| 状態 | 意味 |
| --- | --- |
| `verified` | 原文を取得し、対応する資料本文を確認した |
| `unconfirmed` | 調査したが採用できる対応資料／機能見出しを確認できていない。資料不存在の断定ではない |
| `fetch_failed` | 原文、候補資料、必要な索引の取得失敗。エラー URL と理由を保存する |
| `unresearched` | 台帳がない入力。未処理を 0 件の検索結果と扱わない |

母数はユニークなイベント ID、`occurrences` は重複を含む保存レコード数です。「関連資料あり」と「取得失敗」は独立の指標です。一部の候補を確認できても別候補の取得が失敗すれば、資料ありと取得失敗の両方に数えます。リンク数はこの母数の各更新に付けた資料数の合計で、文書 URL のユニーク数とは異なります。新規追加数はコマンド実行時の台帳差分です。

公開用の全期間件数は `assets/resource-audit.json`、検索版は `assets/search-version.json` でも確認できます。`tests/resource-pages.test.mjs` は日本語／英語の全日次カードと一覧で原文導線、最大 3 件、アーカイブアンカーの存在を検査します。PR のチェック後に merge し、Deploy GitHub Pages の成功と本番のカード／両検索 UI／複数の時期とリリースを確認します。
